> 这是一份**框架**，不是规范。它不规定具体色值、字号和组件样式，只回答「遇到这类设计决定，按什么顺序、依据什么去选」。
> Skill 怎么选、什么时候触发，在 [`AGENTS.md`](./AGENTS.md)。
> 具体决定做出来之后，记进 `docs/design-decisions.md`（日期、决定、理由），以后沿用，不再重新讨论。

## 0. 怎么用

文档里的内容分三种：

- **原则**：稳定，轻易不改。
- **默认值**：没有更好理由时就这么做；有理由可以推翻，推翻时记进设计决定。
- **项目决定**：已经定下的具体选择，优先级最高。

做决定之前先问三件事：这个决定属于哪个区域（见 `AGENTS.md` 第三节）？项目里是否已经有决定？框架里有没有对应默认值？

## 1. 原则

1. **任务优先于装饰。** 界面的用途是读数、比较、判断和操作。能不装饰就不装饰。
2. **风格强度和信息密度成反比。** 工作区安静、克制；入口页和素材可以有性格。风格是点缀，不是底色。
3. **一个页面一个招牌时刻。** 一处明显的设计比五处时髦的效果更好。别处就安静一点。
4. **先层级，后风格。** 先定什么最重要、什么能一眼扫到、什么放在后面，再谈字体和颜色。
5. **用少量的规则撑起一致。** 靠一套小而稳的 token（字体角色、颜色角色、间距阶梯）保持一致，不靠到处复制。
6. **用真实内容做设计。** 真实的数字、真实的中日英文本、真实的长表格，会暴露占位文字看不到的问题。
7. **可访问性和性能是设计的一部分**，不是做完后补的。
8. **不要把「反 AI 味」做成另一种固定模板。** 目标是有判断，不是换一套套路。

## 2. 决策顺序

按这个顺序做，每一步的产出是下一步的输入：

| 步骤 | 要回答的问题 | 产出 |
| --- | --- | --- |
| 1. 信息层级 | 用户来干什么？最重要的三件事是什么？ | 页面的优先级排序 |
| 2. 区域与密度 | 这是工作区、数据区、入口还是素材？ | 风格强度 |
| 3. 布局 | 内容怎么分组、怎么对齐？ | 网格、间距、阅读宽度 |
| 4. 字体 | 几个角色？每种语言用什么？ | 字体角色表 |
| 5. 颜色 | 一个强调色，加什么中性色？ | 颜色角色表 |
| 6. 图表与素材 | 图表怎么选？图标、插画用什么？ | 图表和素材方案 |
| 7. 动效 | 哪里需要动？为什么？ | 动效清单，大多是空的 |
| 8. 文案与多语言 | 语气、三语长度、格式 | 文案约定 |
| 9. 验证 | 真实内容下还成立吗？ | 评审清单（第 11 节） |

## 3. 字体

### 3.1 角色

| 角色 | 用在哪 | 数量 |
| --- | --- | --- |
| 界面与正文 | 几乎所有文字 | 每种文字系统一个 |
| 标题 | 页面标题、大数字 | 可与界面字体同族 |
| 数据与代码 | 表格数字、代码、元信息 | 可选，一个等宽 |
| 点缀 | 引语、空状态文案、批注 | 可选，整个页面最多一处 |

三层的用法来自对 40 个英文字体的整理（[上册](https://x.com/AdrianPunk115/status/2095455845823971411)、[下册](https://x.com/AdrianPunk115/status/2095791816750596304)）：主标题制造第一眼，信息层负责稳定清晰，手写点缀给人味。它的原则是一个版面里别堆很多字体。放到界面里：标题和大数字是第一层，几乎所有内容是第二层，点缀不超过一处。

### 3.2 选择流程

1. **语言覆盖。** 中、日、英三语都要有，英文单独选，不要靠中日文字体自带的欧文。
2. **授权。** 绿灯：OFL、MIT、Apache（Fontsource 会标明），可以自托管。黄灯：免费商用但有条件（MiSans 需署名，阿里巴巴普惠体不能再分发字体文件，HarmonyOS Sans 协议未核实），先读条款再放进仓库。红灯：没有许可证、IPA Font License 这类对嵌入有限制的、商业字体。
3. **字重与可变字体。** 优先可变字体：字重范围宽，文件少。静态字体只加载用到的字重。
4. **跨文字系统的搭配。** 中日文字符铺满方格，Latin 是比例字形，同字号下 Latin 会显得偏小，必要时调整。
5. **数字。** 表格和指标卡要等宽数字（`font-variant-numeric: tabular-nums`），选的字体要支持。
6. **体积。** 中日文字体文件很大，用分片或子集加载，设一个首屏字体体积预算并实测。
7. **用真实内容试排**，再定。

### 3.3 中日文的硬规则

- 用 `:lang()` 为每种语言单独写字体栈，并在页面和内容块上标对 `lang`。中日汉字字形不同，不标会用错字体。
- Latin 字体写在前面，CJK 写在后面（大部分 Latin 字体没有汉字，大部分 CJK 字体带 Latin）。
- CJK 长文行距约 1.7；表格和紧凑组件可以更紧，需要实测。
- 标点位置有地区差异：大陆和日本在方格角落，台湾和香港居中。繁体界面要单独处理。
- 日文标题里欧文很多时，另指定欧文字体，不用日文字体自带的欧文。

### 3.4 按气质选

下表把两册里的商业字体对应到可自托管的免费字体，**气质接近，不是替代品**。授权已用 Fontsource 核实。

| 想要的气质 | 推文里的例子 | 可用的免费字体 | 用在哪 |
| --- | --- | --- | --- |
| 中性无衬线 | Helvetica Neue、Neue Haas、Graphik、Suisse、Univers | Inter、Geist、Instrument Sans、Public Sans、DM Sans | 界面和正文 |
| 几何无衬线 | Futura、Avenir、Circular | Jost、Figtree、Manrope、Sora | 标题或品牌感强的区域 |
| 窄体、工业 | DIN Condensed、Bebas Neue、Franklin Gothic | Bebas Neue、Barlow Condensed、Oswald、Archivo Narrow | 大标题、标签，不做正文 |
| 报刊衬线 | Tiempos、Caslon、Garamond | Source Serif 4、Newsreader、Libre Caslon Text、EB Garamond | 长文、编辑感区域 |
| 高反差衬线 | Didot、Bodoni、PP Editorial New | Bodoni Moda、Playfair Display、Instrument Serif、Cormorant Garamond | 仅大字号标题和大数字 |
| 手写点缀 | Caveat、Sacramento、Allura、Mrs Saint Delafield、Permanent Marker、Rock Salt | 同名字体都有免费版（OFL 或 Apache-2.0） | 空状态、批注，最多一处 |

注意：
- 免费手写体只有拉丁字母。中文点缀用霞鹜文楷，日文用 Klee One，两者同源，搭配自然。
- 高反差衬线的发丝很细，放在中日文旁边会显得单薄，不要做正文。
- Biro Script、SignPainter 等没有核实到免费版本，不直接用。
- 推文里的「字体名加特征」提示词公式适合给 AI 生图写海报素材，但图像模型不能精确调用某个字体，界面里的文字一律用真实字体渲染。

### 3.5 两条路线（默认）

两条路线的中日文底座都是 Noto 家族，混用不会有断层。详细候选见 [`docs/font-candidates.md`](./docs/font-candidates.md)。

- **编辑路线**：衬线标题加无衬线界面，适合报告页、品牌入口、需要「读」的区域。
- **中性路线**：全无衬线，适合高密度的工作区和数据区。

默认：工作区和数据区走中性路线，编辑感强的区域走编辑路线。

## 4. 颜色

### 4.1 用角色，不用色值

| 角色 | 说明 |
| --- | --- |
| 画布、表面、抬升面 | 三级背景 |
| 文字墨色 | 主、次、辅助三级 |
| 边框 | 弱、默认两级 |
| 强调色 | 交互、焦点、当前状态 |
| 状态色 | 成功、警告、严重、危急，配图标和文字 |
| 数据色板 | 与品牌色分开 |

代码里只消费角色，不到处散落色值。

### 4.2 流程

1. 用 2 到 3 个气质词定调。
2. 定中性色的色温（冷、暖或接近纯灰）。
3. 选**一个**强调色相。
4. 在 OKLCH 里推出明暗阶梯。
5. 验证对比度。
6. 深色模式单独选，不是浅色的机械反转，在深色画布上单独验证。

### 4.3 规则

- 大面积用中性色。强调色只给交互、焦点、当前状态和一个主角，不要每个组件都用。
- 对比度：正文至少 4.5:1，大字、图形和边界至少 3:1。
- 颜色不是唯一线索，图表和状态要有形状、文字或图标。
- 状态色是保留的，不借给数据分类用。
- 渐变是配角：平滑的状态过渡、遮罩、刻意营造的氛围才用，不做身份的替代品。

### 4.4 数据色

| 用途 | 做法 |
| --- | --- |
| 顺序（数值大小） | 单一色相，由浅到深 |
| 分类（身份） | 固定顺序分配，不循环；超过 6 到 8 类就合并为「其他」、拆图或改用位置和标签 |
| 发散（正负） | 两个色相，中点用中性灰 |
| 状态 | 用保留的状态色 |

配色在 Claude 里用 `dataviz` 的校验脚本检查色盲可区分度；Codex 里手动检查，至少用一个色盲模拟器过一遍。

## 5. 图表

### 5.1 流程

1. **先问结论。** 这张图要让人看出的那一件事是什么？一张图只承担一个结论，不为了凑数重复表达。
2. **判断是不是图表。** 单个数字、一个状态，用指标卡或大数字，不画图。
3. **按问题选图型。** 比较、构成、趋势、分布、关系、地理，各有对应形状。具体图型和决策树见 `lieflat-charts` 的 `SKILL.md`。
4. **选阅读速度。** 需要几秒内扫到的（周报、监控），用 Glance；愿意停下来细读的（年报、对外故事页），用 Lupi；数据少但想有质感，用 Basics。
5. **最后才配色**（第 4.4 节）。
6. **加交互。** 默认有悬停提示。只给有真实记录的元素加，不给纯装饰加。
7. **渲染出来看**，查标签重叠、溢出、窄屏。

### 5.2 默认的取舍

- 比较少量类目用条形，趋势用折线或面积，占比优先考虑点阵或环形，不默认饼图。
- 条形图不断轴。极端值让它冲出去，或用放大小图，或明说「画不下」。
- 不用双纵轴。两个量纲不同的指标分两张图，或统一成指数。
- 不用 3D、发光、玻璃拟态。
- 两个以上系列必须有图例；少量系列同时直接标注。每个点都标数字是噪音。
- 提供表格视图作为文字替代。
- 深色模式单独选色并验证。

### 5.3 工具

- `lieflat-charts` 是主力：选图型、出模板和视觉。
- `dataviz`（仅 Claude）做校验：配色、悬停、图例、深色、反模式。两者冲突时取更严的那个。
- 它的模板是独立 HTML，用到项目里要移植。Glance 依赖 Chart.js 或 ECharts，打包到本地，不走 CDN。
- 它的字号很小（SVG 最小字号 5.5 到 6.5px），移植时按界面最小字号放大，中日文标签尤其要检查。
- 颜色用项目自己的色板，通过它的 custom 色板规则映射，不直接用内置预设。
- 许可证是 PolyForm Noncommercial：个人项目可用，转商用要换掉或另行授权。

### 5.4 多语言

- 轴标签、图例、提示用 `Intl` 按语言格式化日期、数字、货币。
- 中日文标签长度和换行与英文不同，三种语言都要看一遍。
- 数字用等宽数字。

## 6. 图标与素材

### 6.1 图标

- **一个项目只用一套图标。** 混用会让线宽、圆角和风格不一致。
- 默认 [Phosphor](https://phosphoricons.com/)（MIT，约 1,200 个，六种粗细），极简风格用 Light 或 Regular。备选 [Remix Icon](https://remixicon.com/)（3,200 多个，线性和填充两种，个人和商用都免费）。
- 图标少时直接内联 SVG，多时再用包。
- 线宽与字体字重协调，图标按网格对齐。
- 只有图标的按钮必须有可访问的名称，图标不是唯一线索。
- 不要重画品牌标志。
- 没有许可证的图标库不用（例如 Nyatabi Icons 仓库里没有 LICENSE，风格也偏可爱暖色）。

### 6.2 插画与素材

| 需求 | 用什么 | 注意 |
| --- | --- | --- |
| 空状态、封面、展位图 | `hairline-create`（等距线框，指针响应） | 每个视图最多一个互动图形；它读了减少动画偏好；首次运行会安装 `playwright-core` |
| 单色或双色编辑风格素材 | `mono-color` | 是素材工具，不是界面样式 |
| 报告页、海报型数据页 | `lieflat-charts` 报告模板 | 12 套模板，中英文各一版 |
| 照片 | 保持原样，不套滤镜 | 缩略图另外生成 |

## 7. 布局与间距

- 用一个小而连贯的间距阶梯（例如以 4 或 8 为基数），不写随意的数值。页面级留白可以用 `clamp()` 流动。
- **密度分档**：紧凑（表格、工作区）、标准、宽松（入口、阅读页）。同一个页面里分档要清楚。
- 阅读宽度：长文限制行宽；工作区可以用满宽，但内容块要有最大宽度。
- 边框默认 1px、低对比；圆角小到中；阴影罕用且很柔。能用留白、对比或边框分开的，不加阴影。
- 不要把所有东西都装进圆角卡片。分组靠间距和对齐，不靠盒子。
- 响应式不是把桌面挤小：窄屏要重新组织（表格横滚或改结构、导航折叠），并明确测窄屏和宽屏。

## 8. 动效

- **目的测试**：去掉这个动画，如果什么都没变，它就不该存在。动效解释空间、状态、层级或连续性。
- 时长参考：微反馈很快，下拉和展开快，面板和路由中等。一个可用的区间是快 180 到 280ms、中 360 到 600ms，常规控件不要拖到 700ms 以上。
- 缓动用强减速曲线，例如 `cubic-bezier(0.16, 1, 0.3, 1)`。
- 优先动 `transform` 和 `opacity`，避免动画布局属性。
- 必须尊重 `prefers-reduced-motion`：去掉位移和缩放，保留状态清晰。键盘交互不能依赖动画结束。
- 简单状态变化用 CSS；时间线编排、滚动编排、复杂可中断时才用 GSAP。
- 不做每个元素都动、常驻的环境动画、常规的滚动出现。

## 9. 文案与多语言

- **语气**：清楚、克制、有判断。不夸张，不堆大词。
- **错误信息**：说发生了什么，再说可以做什么。
- **不拼接句子**。句子整体翻译，变量用占位符，三种语言语序不同。
- **留出伸缩空间**。同一句话三种语言的长度不同，别把宽度写死。
- 日期、数字、货币按语言格式化，用 `Intl`。
- 中文大段文案和文章用 `humanizer-zh`（深度改写会先过结构层，处理说穿的道理、整齐的收尾、泛指）。按钮、标签这类微文案不要过度润色。
- 日文敬体（です・ます）还是常体（だ・である）、中文标点和中英文间距，项目内定一次，全站统一。
- 英文长文用 `writing-clearly-and-concisely`。

## 10. 无障碍与性能底线

**无障碍**
- 语义化结构；所有交互元素键盘可达；可见的 `:focus-visible`。
- 对比度见第 4.3 节；颜色不是唯一线索。
- 不依赖悬停；触屏目标尽量不小于 44px。
- 图片有合适的替代文字，装饰图片被忽略。
- 减少动画偏好有对应处理；每个图表有表格视图。
- 正确标 `lang`。

**性能**
- 字体：设预算，用可变字体、子集和分片，只加载用到的字重。
- 图片：响应式交付，保持尺寸稳定，控制布局偏移。
- 只为展示而加的框架或运行时，要有理由。

## 11. 评审清单

完成一个页面或一块界面前，检查：

- **层级**：最重要的三件事一眼能看到吗？
- **区域**：风格强度和这块的信息密度匹配吗？有没有超过一个招牌时刻？
- **字体**：角色清楚吗？三种语言都试过真实内容吗？数字等宽吗？
- **颜色**：强调色克制吗？两种主题都验证了对比度吗？
- **图表**：一张图一个结论吗？有图例、悬停、表格视图吗？没有断轴或双轴吗？
- **动效**：每个动画有目的吗？减少动画偏好有效吗？
- **文案**：三种语言长度和换行都没破吗？有拼接的句子吗？
- **可访问性与性能**：键盘、焦点、窄屏、字体体积。
- **真实内容**：用的是真实数据和文本，不是占位吗？

## 12. 参考资料库

做新的视觉决定、需要外部灵感时，用 [`docs/reference-library.md`](./docs/reference-library.md)。它收录了灵感站点（Landing Love、Land-book、Awwwards、One Page Love、Lapa Ninja、21st.dev、SiteInspire）、结构参考项目，以及中日文排版规范（W3C clreq、heti 等）。

用法的要点：

- 参考是**证据和灵感，不是模板**。先写下一个设计问题，选一类参考，看 1 到 3 个页面，提取可度量的原则，再翻译成自己项目的 token。
- 不复制布局、代码、文案、照片和品牌素材。
- 记录实际看过哪些、每个影响了什么决定，记进 `docs/design-decisions.md`。没看过的站点不引用为证据。
- 参考和项目已有决定冲突时，项目决定赢。
- 资料库以编辑型内容站为主，数据密集界面的参考还没建立；遇到这类需求，先明说缺口，再去找，不要硬套。

## 13. 依据与未验证
