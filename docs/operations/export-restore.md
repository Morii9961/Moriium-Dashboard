# 从导出包恢复到新实例

这是 P6.1 的离线迁移工具。它接受设置中的「导出全部数据」产生的完整包，不接受「只导出快照原文」或经其它压缩工具重打包的 ZIP。日备份的数据库恢复仍沿用原操作说明。

实际迁移前先保留原库、备份和导出包，在停用旧实例写入后生成最终包，避免两边继续写入而分叉。P6 工程准备的授权不代表已经授权正式恢复或部署。

## 先检查

在仓库根目录，使用项目要求的 Node / pnpm 版本运行：

```text
pnpm data:restore --check <export.zip>
```

仅在内存中校验和构建数据库，不创建目标目录、不启动服务、不访问包内链接。成功输出 `status: checked`、导出时间与各类记录数量；失败退出码为 1，只打印固定错误码和用法。

检查包括 ZIP 边界、CRC、名称、元数据字段、数量、所有引用、快照原文与内容指纹、三语字段、封面容器、SQLite 外键与完整性。快照重用协议检查及代码块提取规则，原文逐字节保留；额外拒绝重复 JSON 键及解码后的疑似令牌。包内容的校验不证明来源可信；应使用自己保管的原始导出包。

## 写入新的绝对目录

```text
pnpm data:restore --apply <export.zip> --target <NEW_ABSOLUTE_DIR>
```

父目录必须已经存在，最终目录必须**不存在**，已有空目录也拒绝。不会读取 `MORIIUM_DASHBOARD_DATA` 作为恢复目标；必须通过 `--target` 明确指定。拒绝仓库内、常见同步盘内的目录，解析父目录链接后再次检查边界，最终目录通过排他创建预留。

全部校验通过后，先把内存库写入新目录里的 `.restore.sqlite` 并复核，再用同目录硬链接排他创建 `dashboard.sqlite`，最后删除临时名字。目标文件系统必须支持硬链接（开发使用 NTFS，Linux CI 验证 Linux 文件系统）。失败时保留新建目录供检查，不自动递归删除，也不会覆盖已有目录。成功才输出 `status: restored`；`serviceStarted` 始终为 `false`。

Linux 新目录申请权限 `0700`、数据库申请 `0600`；Windows 的访问控制由父目录 ACL 决定。它不证明断电场景的持久性；停止、重启与恢复演练属于 P6.5 的部署验收。

## 保留哪些数据

保留项目、当前及归档快照、批次与撤销状态、人工验收、条目处理状态、手动里程碑、任务及原始来源、成果与回收站、封面。ID 与引用不重排。新增导出元数据会显式记下批次 ID 和报告备注；旧 format 1 包缺少这两项时，从批次结果和快照归属重建。

今日焦点保留导出日；恢复到另一天时仍按原规则显示当天空安排，不把旧安排挪到今天。规范化结果和提醒按当前协议规则从原文重新生成；指纹不匹配时拒绝，不悄悄改写。恢复事件记一条 `data.restore` 操作记录；原操作日志不在导出格式里。

导出格式本来就不包含会话、口令哈希、服务端配置和设置，因此恢复命令也不恢复这些内容。登录与服务配置需在 P6 后续步骤单独设置。不会继承认证状态或自动切换正式数据源。

## 核对后再启用

人工核对输出数量和抽查项目、历史、任务及成果；确认后，另行将服务的 `MORIIUM_DASHBOARD_DATA` 指向新目录，再启动服务。不要让本机和 VPS 同时成为正式写入源。正式迁移、访问方式、口令设置及 VPS 上线仍须 Morii 在对应步骤明确授权。
