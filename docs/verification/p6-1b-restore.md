`pnpm verify`：355 项测试、19 个测试文件通过；全仓与三个包的类型检查通过；公开树审计通过（当次 345 个文件）；11 条既有提醒，无新增提醒。后续仅补充文档，不把测试结果重复记成独立验收。此证据来自 Windows；准确 PR 提交的 Windows / Linux CI 另由 GitHub 保存。

恢复测试全部使用内存库、系统临时目录和虚构 `demo.*` 内容：

- 项目、批次、人工验收、处理状态、手动里程碑、任务、成果、封面及全部历史按表逐列比较；ID、原文、报告归属、引用与回收站状态一致。再次导出的条目逐项一致；恢复后的批次可撤销。
- 兼容旧 format 1 缺少的批次 ID / 报告备注；UTF-8 BOM 与明确提取过的代码块原文字节不变；过期焦点没有移动到恢复当天。
- 直接执行 CLI 子进程：检查与恢复退出 0，非法包或参数退出 1，诊断不回显包内容或私有路径；不启动服务。
- 检查模式零落盘；写入模式只允许不存在的目录；已有库逐字节未变，已有空目录、目录链接、仓库别名、同步目录和相对路径均拒绝。损坏包不会创建目标目录。
- 拒绝不匹配的数量与指纹、缺少或额外文件、坏引用、非法字段类型与链接、项目名中的双向控制符、疑似令牌和已重算 ZIP CRC 的坏封面。容器边界的五项独立测试见 P6.1a。
