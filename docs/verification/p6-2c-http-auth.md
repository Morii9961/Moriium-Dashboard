# P6.2c · 登录认证接入 HTTP

2026-10-17，分支 `claude/p6-http-auth`，基于合并了 #31–#34 的 main。设计见 [ADR 0005](../adr/0005-private-auth-store.md)，开启方法见 [口令工具说明](../operations/auth-setup.md#开启登录认证)。

## 做了什么

- 配置：`MORIIUM_DASHBOARD_AUTH=required` 加上认证库目录才开启；只给目录、只给代理开关、未知取值、相对路径都拒绝启动。对外来源只接受不带路径的 https，并且必须同时开启认证，加入允许的 Host 与 Origin。服务仍只监听 `127.0.0.1`。
- 启动：开启认证时先打开认证库并确认已有账户；文件不存在时不新建，任何异常都打印固定说明并以退出码 1 结束，不输出路径。
- 默认拒绝：中间件放在 Host 与写请求检查之后，`/api` 与 `/api/*` 只放行登录、退出、会话状态、健康检查四个完全相同的路径，其余要求有效会话。认证库在请求中出错时返回 503。前端页面不含数据，照常提供。
- 接口：`POST /api/auth/login` 仍要求本站 Origin 与自定义写请求头，成功返回 204 和 `__Host-` cookie，并轮换携带的旧会话；错误统一为 `invalid_credentials`，锁定返回 429 与 `Retry-After`。`POST /api/auth/logout` 无会话也能清掉 cookie；`POST /api/auth/revoke-all` 需要会话。`GET /api/auth/session` 告诉前端是否需要登录。
- 日志：登录失败与锁定只写固定格式和校验过的 IP；`X-Real-IP` 只在显式信任代理、且请求来自本机回环时采用。

## 验证

新增 `apps/server/test/auth-http.test.ts` 10 项，使用真实固定成本 scrypt 和虚构账户：无会话时各业务接口与写请求 401、页面外壳可取；缺写请求头的登录 403；错误口令和换用户名得到同样的 401，日志不含提交内容；cookie 属性、凭会话访问、退出后失效；撤销全部需要会话且使所有会话失效；伪造或格式错误的 cookie 被拒；锁定时 429 且不核验口令；认证库失效时 503 且仍不放行；未开启认证时行为不变、没有登录接口；启动不新建认证库；各种半配置与不合格来源被拒绝。

`pnpm verify` 通过：387 项测试 / 22 个文件、类型检查、公开树审计（368 个文件），11 条既有提醒。审计把一个测试地址误认成邮箱，已在白名单登记理由。

真实账户、正式实例和服务器均未操作；登录界面、TLS 与反向代理配置由后续工作包完成。
