## 发布路径审查

| 重点 | 代码结论与边界 |
| --- | --- |
| 首次 `--prepare` | 完成指定提交的解包、依赖安装和构建后直接退出；不创建/改变 `current`，不调用 systemctl |
| 数据与账户顺序 | 文档要求在构建输出目录恢复数据、由 Morii 本人在 TTY 设置口令，再按同一个完整 SHA 激活；prepare 不执行恢复或口令设置 |
| restart 失败 | restart 位于 `if ... && healthy` 条件中，非零进入失败分支，不被 `set -e` 提前截断 |
| 健康失败 | 最多 30 次探测，连接超时 2 秒、单次总超时 3 秒；不能说总共仅 30 秒。失败不会写成功发布记录 |
| 自动重试停服 | 失败分支先调用 `systemctl stop`，成功后才决定是否回退；systemd 模板为 `Restart=on-failure`。stop 若自身失败，`set -e` 会退出并保留链接，不继续启动旧代码；此时不能宣称已经停服，须人工核对服务状态与 journal |
| 自动回退前提 | 有不同的前一版本，且 `diff -qr` 对两个迁移目录返回 0；新增、同数量内容变化，以及目录缺失/无法读取等非零结果均拒绝自动回退 |
| 不可回退 | 保留当前链接、发布目录与数据库现场，停服等待另行授权的人工恢复；不自动覆盖数据库 |
| 回退仍失败 | 再次 stop，返回非零；第一次发布没有旧版本或重试当前版本失败，也进入停服人工处理路径 |
| 主线 Usage 迁移 | 第 11 号迁移与旧版不同，应触发保守拒绝自动回退；这里由代码比较证明，未宣称执行过真实 SQLite 迁移 |

上述停服结论以 systemctl 命令成功为前提。脚本不代替现场服务状态、数据完整性或备份可恢复性的验收。
