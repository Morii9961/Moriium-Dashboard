## 复现与修复

旧脚本在切换代码后直接执行 `systemctl restart`。由于 `set -e`，启动命令返回非零时会立即退出，绕过后面的健康检查与回退分支。首次部署文档又要求在恢复数据、设置账户前调用这个发布流程。

- 新增 `release.sh --prepare <ref>`：只构建指定提交，不改变 `current`，不调用服务管理命令；先恢复数据和设置账户，再激活完整提交 SHA。
- 重启失败和健康检查失败进入同一个恢复分支。健康请求增加连接和总超时。
- 失败后先停服务，避免 systemd 不断重试。只有前后迁移目录内容相同时才尝试回退；迁移增加、内容变化或无法核对时都保留当前代码并停服，等待人工核对数据库与备份。回退版本也失败时保持停服。
- 重试当前提交也执行启动验证，不再仅凭 `current` 相同就宣称无需发布。
- 更正文档：SQLite 备份与导出 ZIP 用途不同；跨迁移人工恢复不能靠重复调用仍会保守拒绝的回滚脚本完成。

## 验证

- 修改前运行新回归脚本，旧版本在 `--prepare` 场景错误启动并切换代码，测试以非零退出。
- `pnpm verify`：392 项测试 / 23 个文件、类型检查、公开树审计通过；Biome 无错误，保留 11 条既有警告。
- `bash scripts/deploy-release.test.sh`：11 个虚构场景，包括首次与已有实例只构建、实际构建路径、成功发布、启动失败回退、健康检查失败回退、新增迁移保护、首次启动失败、同数量迁移内容变化、重试当前提交、回退也失败。
- Windows Git Bash 无创建原生符号链接的权限，因此本机回归对链接命令使用指向文本的模型；其他命令仅模拟 Git、包管理器、服务与健康探针。CI 的 Linux 步骤使用真实符号链接和文件切换，其结果须另行核对。
- 初次在 Windows 沙箱中运行现有测试遇到临时模块文件缺失；把临时目录移进仓库又触发了测试本来就有的数据目录保护。未修改产品边界，改在正常 Windows 临时目录运行后全量通过。

这些结果覆盖本次修复与现有自动检查，不代表真实 Linux 服务、Nginx、证书、备份恢复、产品验收或 VPS 部署完成。
