# P6.2a · 登录底层验证

2026-10-17，代码依据 `ef7eee6fcdd22e6ddf615fb7684d2953a03856ad`；在 P6.1b 分支上堆叠。认证存储与策略见 [ADR 0005](../adr/0005-private-auth-store.md)。本包仅有内部函数，没有连接主服务、登录页面、HTTP 接口或口令设置入口。

`pnpm verify` 通过：369 项测试 / 20 个文件，全仓及三包类型检查、公开树审计（当次 354 个文件），仍为 11 条既有提醒。文档随后补齐，不重复记成新验收。Windows 本地证据与准确 PR 提交的 Windows / Linux CI 分开记录。

14 项新增测试使用真实固定成本 scrypt，无降级成本或模拟 KDF；账户、口令、库与会话全部是隔离虚构样本：

- 随机盐、正确与错误口令、尾部空格、中日文字符；短口令、过长输入、不完整 Unicode 和坏哈希编码被拒绝。
- 只能创建一个账户，已配置账户不能被静默覆盖。并发核验有界，核验期间凭据修订改变不会签发会话。
- 每次登录签发新值并撤销携带的旧值；只存摘要，最多保留五个，最后签发的仍可用。cookie 的 Host 前缀、Secure / HttpOnly / Strict、路径、退出属性和注入拒绝均覆盖。
- 空闲与绝对超时、时钟回拨、退出、撤销全部、凭据修订变化均失效；活动不会延长绝对寿命。
- 未知账户与错误输入返回相同失败；日志只存固定事件，不含提交的文字。账户与全局限速分别保留，重开库后限速及有效会话不丢失，拒绝请求不延长锁定窗口，事件记录最多一千条。
- 相对、仓库内、同步目录和目录目标被拒绝；已有业务库或未知结构不会被添加认证表。Linux 文件权限断言由 CI 检查，Windows 仍依赖真实父目录 ACL。业务导出不包含认证哈希。

按 `code-review-and-quality` 五项自查：没有外部请求、依赖或业务迁移；固定 SQL 和固定 KDF 参数，登录预留次数在异步计算前完成，身份重新检查与会话写入在同一事务；认证表、会话和日志均有数量边界。会话签发是受信内部函数，后续路由只能在成功认证后调用，不能暴露成直接签发接口。

真实账户、口令、数据、正式实例、VPS、可信代理与 fail2ban 均未操作。HTTP 默认拒绝、CSRF、登录 UI 和实际 TLS 的安全性不由本包证明，必须在后续接入包验证。没有代填真实试用或产品验收，也未生成或导入项目状态快照。
