# P6.3–6.5 · 部署模板与验收清单

2026-10-17，分支 `claude/p6-deploy-templates`。只在仓库里准备模板、脚本和文档，没有连接或改动任何服务器，也没有选定访问方式。

## 内容

- `deploy/`：环境变量样例、systemd 服务（专用用户、只写数据目录、常见的隔离项）、Nginx 公网与私网两份站点配置和共用转发片段、fail2ban 过滤器与 jail 样例、发布 / 回滚 / 拉回备份三个脚本。
- [部署说明](../operations/deploy.md)：从建用户到设置口令的顺序，数据迁移、回滚和备份的做法。
- [部署验收清单](../operations/deploy-checklist.md)：P6.5 要在 VPS 上逐项实测的内容。

## 取舍

- 两种访问方式都要求 HTTPS，因为会话 cookie 带 `Secure` 与 `__Host-` 前缀。
- 发布按提交解包到独立目录，用符号链接切换；健康检查失败自动切回。旧程序会拒绝比自己新的数据库结构，所以回滚脚本在跨迁移时拒绝，并指向迁移前备份。
- 认证库不备份：只含口令哈希、会话和限速，丢失后由 Morii 重新设置；口令哈希不离开服务器。业务备份由服务每天生成，本机脚本拉回后做 SQLite 完整性检查。
- Nginx 对登录接口另做每分钟 10 次的来源限速；应用自身的账户与全局限速保持不变。fail2ban 匹配服务日志里只含来源 IP 的固定行。

## 检查

三个脚本通过 `bash -n` 语法检查；本机没有 shellcheck。确认 `restore/command.ts` 与 `auth/setup.ts` 可以直接用 node 调用（服务用户没有登录 shell）。公开树审计通过，仓库里没有真实地址、域名或证书。模板未在真实服务器上运行过，正确性以 P6.5 清单的实测为准。
