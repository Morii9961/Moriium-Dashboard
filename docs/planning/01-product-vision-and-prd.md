# 01 · 产品愿景与 PRD

> 状态：已获批（2026-10-12）。决定记录见 [`docs/design-decisions.md`](../design-decisions.md)。

## 1. 定位

Moriium Dashboard 是 Morii 一个人用的工作台。打开它，30 秒内知道今天做什么、哪个项目在等自己拍板、哪些报告该更新了、最近做成了什么。

它把三样东西放在一起：
- **项目状态**：各项目的 Agent 按统一协议写的快照，Morii 手动导入。
- **Morii 自己的判断**：今日焦点、验收、决定、暂停。
- **做成的东西**：软件版本、照片集、视频、验收通过的里程碑。

它不是任务管理软件，也不是实时运维平台。信息多不是目标，信息可信、看得快、维护省事才是。

本项目叫 Moriium Dashboard，与 Morii OS 没有关系。委托书里出现的「Morii OS」「Personal Command Center」都指本项目。

## 2. 目标

| # | 目标 | 怎么判断做到了 |
| --- | --- | --- |
| G1 | 30 秒看清 | 用真实数据，Morii 在 30 秒内答出 02 第 1 节的四个问题 |
| G2 | 每条状态都有来源 | 屏幕上任何一个状态，都能追到一份快照（时间、Agent、依据）或 Morii 自己的记录 |
| G3 | 三种「完成」分开 | Agent 自报、有仓库或测试证据、Morii 验收，在任何地方都不合并显示 |
| G4 | 维护省事 | 每周为在推进的项目生成并导入快照，总共不超过 10 分钟；每天定焦点不超过 1 分钟，而且可以不做 |
| G5 | 不制造焦虑 | 没有连续天数、分数、排行；过期只是提示；可以暂停项目、选择低精力或休息 |
| G6 | 做成的东西被看见 | 成果和验收通过的里程碑在概览上和待办一样显眼 |

## 3. 明确不做

- 不读取 Codex 或 Claude 的实时会话，不显示 Agent「在线」「正在运行」。
- 不在后台自动拉取、监视文件夹或定时导入。
- 不估算没有依据的完成百分比，不把 null 画成 0%。
- 不做团队协作、多用户、公开分享页。
- 不做时间追踪、番茄钟、连续打卡、生产力分数。
- 不把 token 用量当作进度。Moriium 的活动数据如果以后接入，只能标为「用量」，与进度分开。
- 首版不做：日历同步、课程表、复杂统计图、跨服务双向操作、自动化工作流、GitHub 同步。
- 不替 Agent 改快照内容，不执行快照里的任何东西。

## 4. 使用场景

| 场景 | 发生什么 |
| --- | --- |
| 早上或开始工作时 | 打开概览，选精力，定一到三件焦点，处理一两条待决定 |
| 结束一段 Agent 会话后 | 在会话里输入「生成项目状态快照」，回 Dashboard 导入；看这次改变了什么 |
| 每周一次 | 为本周有进展的项目各生成一份快照，一次拖入多个文件导入；顺手处理过期提示 |
| 验收一个里程碑 | 在项目详情看证据，点「通过」或「退回」并写一句 |
| 做成一件作品 | 在作品页登记，加一张封面和一句话 |
| 状态不好的一天 | 选「低」或「休息」，页面只留最必要的东西 |
| 在手机上 | 看状态、处理待决定、勾焦点 |

## 7. 关键流程

**F1 生成并导入快照**
1. 在项目的 Agent 会话里输入「生成项目状态快照」。
2. Agent 更新 `docs/status/` 下两份文件，回复三五行回执。
3. 在 Dashboard 点「导入」，拖入文件（可以多个）。
4. 看预览：状态、位置（最新 / 进历史 / 重复）、变化、错误和提醒。
5. 有错误：点「复制给 Agent 的修复说明」，回会话粘贴，重新生成。
6. 确认导入，看到项目的新状态；不对就撤销。

**F2 处理一条待决定**
1. 在概览的「需要你决定」看到条目。
2. 点「已决定」，写一句结论；或「稍后」选日期；或「不适用」。
3. P1：点「复制决定给 Agent」，把结论带回项目会话。
4. 下一份快照仍列出这条时，Dashboard 提醒「你已决定过」。

**F3 验收里程碑**
1. 概览或项目详情里出现「待你验收」。
2. 展开证据，必要时去仓库或线上看。
3. 点「通过」或「退回」，写一句说明。
4. 通过的里程碑出现在「最近交付」。

**F4 定今日焦点**
1. 选精力。
2. 从下一步、任务或待决定里点「加入今日焦点」，或直接输入。
3. 最多三件。做完勾掉；没做完第二天不会自动顺延，也不会提醒。

**F5 登记成果**
1. 作品页或概览点「登记成果」。
2. 填标题、类型、日期，可选项目、链接、封面和一句话。

**F6 低精力或休息**
1. 选「低」：页面只留焦点和最紧要的决定。
2. 选「休息」：只留一句话和焦点区，过期提示也不显示。

**F7 暂停项目**
1. 项目设置里把关注状态改为「已暂停」，可写一句原因。
2. 项目收进「已暂停」，不再计算过期，不出现在概览主列表。

**F8 第一次使用**
1. 打开后看到预置的六个协议项目，都显示「还没有快照」。
2. 按页面上的三步，为每个项目生成快照并一次导入。
3. 从建议列表里添加需要的手动项目。

## 8. MVP 的产品验收

MVP 完成的标准不是功能列表打满，而是下面四条都成立：

1. **30 秒测试**：导入至少五个项目的真实快照后，Morii 在 30 秒内答出四个问题。
2. **来源抽查**：随机点开十个状态元素，每个都能追到快照或 Morii 的记录。
3. **一周试用**：Morii 实际用一周，期间每个在推进的项目至少导入一次，导入过程中不需要求助文档。
4. **没有虚假进度**：所有 `overall_progress` 为 null 的项目都没有进度条；成熟项目显示为「上线准备」而不是低完成度。
