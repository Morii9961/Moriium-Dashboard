# 02 · 信息架构与 UX/UI 方案

> 状态：已获批（2026-10-12）。决定记录见 [`docs/design-decisions.md`](../design-decisions.md)。
> 线框里的项目内容是**示意**，不代表各项目的真实状态。真实内容要等第一批快照导入后再用来校验设计。
> 具体色值、字号、字体在 P2 阶段和 Morii 逐项商定后记入 `docs/design-decisions.md`，这里只给方向和默认值。

## 1. 出发点

打开 Dashboard 的 30 秒里，Morii 应该能回答四个问题：

1. 今天最重要的一到三件事是什么？
2. 哪个项目在等我决定或验收什么？
3. 哪些项目的报告过期了？
4. 最近做成了什么？

页面层级按这四个问题排。凡是不帮助回答它们、也不帮助完成一次操作的元素，不放在概览上。

区域划分（见 `AGENTS.md` 第三节）：概览、项目、Agents、计划都是 **S1 工作区**，风格 Skill 不介入；里程碑格、时间带这类小图属于 **S2**；作品页的封面墙偏 S4，但 MVP 里也按工作区处理。

## 2. 导航结构

```text
概览 Overview          /
  需要你决定（全部）      /inbox
项目 Projects          /projects
  项目详情              /projects/:id            概况 · 历史 · 成果 · 任务 · 设置
  快照对比              /projects/:id/history?compare=a,b
Agents                /agents
  单个 Agent            /agents/:agent
作品 Studio            /studio                   MVP：成果记录
计划 Planner           /planner                  MVP：今日焦点、精力、任务
导入                   全局对话框；/imports 查看导入记录
设置                   /settings                 项目登记、显示、数据
```

**相对委托书的调整和理由**

| 调整 | 理由 |
| --- | --- |
| 保留五个一级页面 | 五个页面分别对应「今天、项目、报告来源、作品、时间」，互不重叠；再多就要靠记忆找东西 |
| 导入做成全局动作，不占一级导航 | 导入是一个动作，不是一个要停留的地方；任何页面都可能需要 |
| 「需要你决定」不单独成页，放在概览，另有 `/inbox` 看全部 | 它是 30 秒问题的第二个，必须在首屏；单独成页会让它离开首屏 |
| Studio 和 Planner 的 MVP 各只做一小块 | 委托书第 8 节要求严格控制首版。作品登记和今日焦点是 MVP 必须的，其余后置 |
| 设置独立 | 项目登记、数据导出、备份要有固定位置，但不常用 |

**跨页面的统一做法**
- 项目标签（项目名 + 小字 ID）在任何地方点击都进入项目详情。
- 「加入今日焦点」「转为任务」两个动作出现在下一步、待决定和任务上，行为一致。
- 命令面板 `Ctrl/⌘ + K`（P1）：跳到项目、导入、新建任务、登记成果。
- 时间统一显示为相对时间加绝对时间（悬停或聚焦时显示，读屏直接读绝对时间）。

## 3. 布局与响应式

| 宽度 | 导航 | 内容 |
| --- | --- | --- |
| ≥ 1440 | 左侧导航 224px | 主列最大 1120px；概览增加右侧窄栏（报告新鲜度、Agent 最近报告） |
| 1280 到 1439 | 左侧导航 224px | 单主列 |
| 1024 到 1279 | 左侧导航收为 64px 图标栏，图标有可见的文字提示 | 单主列 |
| 768 到 1023 | 顶栏 + 抽屉导航 | 表格保留，次要列隐藏 |
| < 768 | 底部五个标签 + 顶栏（导入、设置） | 表格改为卡片列表；对话框改为全屏 |

- 间距以 4 为基数，常用 4、8、12、16、24、32、48。
- 密度分档：项目表格、历史、对比为紧凑档；概览为标准档；作品页为宽松档。
- 手机上的重点是看和处理（看状态、处理待决定、勾今日焦点）。导入在手机上也能用（选择文件），但按桌面优先设计。

### 4.2 各区块

| 区块 | 内容 | 排序与上限 | 动作 |
| --- | --- | --- | --- |
| 今天 | 日期、精力四档、今日焦点（≤ 3 件） | 焦点按添加顺序，可拖动或用键盘调整 | 勾选完成、添加、移除 |
| 需要你决定 | 汇总三类：各项目当前快照里未处理的 `needs_morii`；Agent 报告完成、等你验收的里程碑；你「稍后」到期的条目 | 按来源快照时间倒序，显示 5 条 | 已决定（写一句结论）/ 稍后 / 不适用；验收项跳到对应里程碑 |
| 项目 | 关注中的项目：名称、迷你阶段轴、阶段名、第一条 P0 下一步、阻塞数与待决定数 | 先按你设的优先级（焦点、普通、靠后），再按待决定数 | 点击进详情；没有快照的显示「导入」 |
| 最近交付 | 近 14 天登记的成果 + 你验收通过的里程碑 | 按日期倒序，最多 6 个 | 登记成果 |
| 报告新鲜度 | 每个协议项目一行：上次快照的相对时间 | 过期的排前 | 点击打开预选该项目的导入对话框 |
| Agent 最近报告 | 每个 Agent 最后一份报告的时间，下方注明「这是导入时间，不是在线状态」 | — | 进 Agents 页 |

### 4.3 精力状态

精力是 Morii 自己选的一个词，用来调整页面给出的信息量，不是一个要追踪的指标。

| 精力 | 概览的变化 |
| --- | --- |
| 充足 / 一般 | 正常显示 |
| 低 | 只显示「今天」和「需要你决定」里的 P0 与有截止日期的条目；其余收起为一行「其余内容已收起 [展开]」 |
| 休息 | 只显示一句「今天是休息日，需要你决定的事会等你」和「今天」区块；过期提示不显示 |

- 精力只影响当天，第二天回到未选择。
- 不画精力曲线，不做统计。是否保留历史记录，留到 Planner 的复盘功能时再问 Morii。

- **进度怎么表达**：

### 5.3 项目的关注状态

关注状态是 Morii 对项目的安排，和快照里的 `stage` 是两回事：

| 关注状态 | 含义 | 在概览里 |
| --- | --- | --- |
| 进行中 | 现在在推进 | 显示 |
| 等待中 | 在等外部条件（审批、他人、时间） | 显示，排在后面 |
| 酝酿中 | 想法阶段，还没开始 | 不显示 |
| 已暂停 | 主动停下 | 收起为「已暂停 · N」；不计算报告过期 |
| 已归档 | 结束 | 不显示 |

暂停是正常的工作方式。暂停的项目不变灰到看不清，也不出现任何提醒。

### 5.4 进度展示的要求（2026-10-12 Morii 特别强调）

MVP 范围不变，但项目进度的展示是首版的重点，不能只是把快照字段排出来。每个项目的卡片和详情页都要回答委托书里的四个问题：

| 问题 | 卡片上 | 详情页上 | 数据来源 |
| --- | --- | --- | --- |
| 做到哪里了 | 迷你阶段轴 + 阶段名 + 里程碑格 | 完整阶段轴；「进入当前阶段：10月2日」；里程碑表 | `stage`、`milestones`；进入日期由历史快照推算 |
| 离可用或上线还差多少 | 一行「还差什么」 | 同一行，可展开到具体条目 | 未完成里程碑、阻塞、待你处理的事 |
| 下一步是什么 | 第一条 P0 下一步，没有 P0 就第一条 P1 | 全部下一步，按优先级分组 | `next_actions` |
| 需要你做什么 | 待决定数 + 待验收数 | 待决定和待验收放在详情页最上面 | `needs_morii`、`human_acceptance`、Morii 的验收记录 |

**「还差什么」行**：完全由快照计算，不做估算。例如：

```text
还差：4 个里程碑未完成（其中 1 个受阻）· 1 个阻塞 · 等你 2 件（1 个决定、1 次验收）
```

- 全部里程碑已完成、没有阻塞时，按阶段改写：`launch_preparation` 写「功能成熟 · 等待上线」，`live` 写「已上线」，`maintenance` 写「维护中」。主站和 Gallery 这类成熟项目因此显示为「成熟、在等上线」，而不是一个低百分比。
- `unknown` 状态的里程碑单独计数（「另有 2 个状态未知」），不算未完成，也不算完成。
- 没有快照时写「还没有快照」，不写 0。

**核心里程碑**：持续研发的项目（Runtime、Memory）里程碑可能很多。Morii 可以在项目设置里勾选「核心里程碑」（按里程碑 `id` 保存，新快照来了也不丢）。卡片上的里程碑格只显示核心里程碑；没勾选时显示全部，超过 12 个时只显示进行中、受阻和最近完成的，并写「另有 N 个」。详情页始终显示全部。

**进入当前阶段的时间**：从历史里找出连续处于当前阶段的最早一份快照，写「进入当前阶段：10月2日（据快照）」。只有一份快照时写「首份快照即为此阶段」。这是对历史的如实读取，不是预测。

**历史对比**：任选两份快照对比、历史上方的时间带，都从 P1 提到 MVP（P0）。

**手动项目也有进度**：创作、生活、学习、探索类项目没有快照，但可以由 Morii 维护一组简单的手动里程碑（标题、状态、可选的目标日期），用同一个里程碑格显示，证据标签写「你记录的」。再加上「正在」「下一步」和关键日期（例如出发日），手动项目的卡片也能回答「做到哪里、下一步是什么」。手动里程碑可以不填。

**验收方式**：P4 结束时，用六个项目的真实快照逐个过一遍，Morii 在每个项目的卡片上 10 秒内能答出上面四个问题；不顺的地方在 P5 之前改完。

## 7. 作品 Studio（MVP：成果记录）

## 11. 状态表达

### 11.1 里程碑状态

| 值 | 图形 | 文字 | 颜色角色 |
| --- | --- | --- | --- |
| `not_started` | 空心圆 | 未开始 | 次要文字 |
| `in_progress` | 半实心圆 | 进行中 | 主文字 |
| `blocked` | 带斜线的圆 | 受阻 | 严重（砖红） |
| `done` | 对勾 | 完成 | 正常（灰绿） |
| `unknown` | 虚线圆 + 问号 | 未知 | 次要文字，不用强调色 |

### 11.2 证据与验收

| 层 | 写法 | 外观 |
| --- | --- | --- |
| 自报 | 「自报」 | 虚线描边标签 |
| 仓库证据 / 有测试记录 | 「仓库证据」「有测试记录」 | 实线描边标签 |
| 据报告已验收 | 「据报告已验收」 | 实线描边 + 小对勾 |
| 你已验收 | 「你已验收 · 日期」 | 浅色填充 + 对勾 |
| 你已退回 | 「你已退回 · 日期」 | 浅色填充 + 回退箭头 |

### 11.3 阶段轴

- 已经过的阶段：实心点，墨色。
- 当前阶段：带外圈的实心点，雾蓝，下方写阶段名。
- 未到的阶段：空心点。
- `paused`：整条轴降为弱对比，当前位置保留，旁边写「已暂停」+ 暂停图标（灰紫）。
- `unknown`：轴画成虚线，写「阶段未知」。

### 11.4 数据状态

| 状态 | 什么时候 | 怎么显示 |
| --- | --- | --- |
| 没有数据 | 从未导入快照 | 「还没有快照」+ 三步说明 + 导入按钮 |
| 未知 | 快照里写了 `unknown` | 照实显示「未知」，不当作 0，不算进完成数 |
| 过期 | 超过新鲜度阈值 | 土黄图标 +「报告已 18 天」，不变红，不弹窗 |
| 矛盾 | 快照内部或与你的验收记录冲突 | 小提醒图标，展开说明哪两处冲突 |
| 已暂停 | 关注状态或 `stage` 为暂停 | 灰紫标签，不计过期 |
| 加载中 | 首次请求 | 静态骨架，不做闪烁动画 |
| 服务未连接 | 前端连不上本机服务 | 顶部横幅「本机服务没有运行」+ 启动方法；已加载内容保留 |
| 操作失败 | 写入失败 | 说清发生了什么、数据有没有变、可以做什么 |
| 同步失败 / 权限不足 | 以后的 GitHub 同步 | 保留上次成功的数据，标注「GitHub 数据停在某时，原因：令牌无权限」 |

**绝不出现的东西**：把 null 画成 0%；把导入时间说成「在线」；用颜色代替文字；为了好看给没有数据的地方填假数据。

## 13. 视觉方向（默认值，P2 逐项商定）

| 项 | 默认方向 | 依据 |
| --- | --- | --- |
| 气质词 | 冷静、清楚、私人 | 委托书第 6 节 |
| 中性色 | 偏冷的灰，带极轻的蓝调 | 与雾蓝强调色同一色温 |
| 强调色 | 雾蓝，一个色相；只用于交互、焦点、当前阶段 | 委托书第 6 节；参考 Moriium 的雾霾蓝一族，但重新在 OKLCH 里推导，不沿用色值 |

| 场景 | 做法 | 时长 |
| --- | --- | --- |
| 对话框开合 | 淡入 + 0.98 → 1 缩放 | 200ms |
| 抽屉导航 | 位移 | 280ms |
| 提示出现 | 淡入 + 少量位移 | 180ms |

缓动统一用 `cubic-bezier(0.16, 1, 0.3, 1)`。减少动画偏好下只保留透明度变化。没有常驻动画。

## 15. 文案与多语言

- 界面源语言为简体中文，另有日文和英文。界面文案用 ICU 消息格式，整句翻译，不拼接。
- **快照内容不翻译**。协议规定摘要是中文，所以快照里的文字块一律标 `lang="zh-Hans"`。日文界面里显示这些内容时，汉字仍按中文字形渲染，不会被日文字体错误显示。
- Morii 自己输入的任务、成果、决定结论，保存时记录输入时的界面语言作为 `lang`。
- 日期和数字用 `Intl` 按界面语言格式化；相对时间用 `Intl.RelativeTimeFormat`。
- 时间存 UTC，同时保留快照原始的时区偏移；默认按 Asia/Shanghai 显示，详情里显示原始写法。
- P2 一次定下：日文界面用敬体还是常体；中文界面里中英文之间是否加空格。
- 文案语气：说清事实，不催促，不庆祝。错误信息先说发生了什么，再说可以怎么做。

**关键文案的三语草稿**

| 键 | 中文 | 日本語 | English |
| --- | --- | --- | --- |
| 待决定区标题 | 需要你决定 | あなたの判断が必要 | Needs your decision |
| 报告时间说明 | 这是导入时间，不是在线状态 | 取り込んだ時刻です。稼働状況ではありません | Import time, not online status |
| 自报 | 自报 | 自己申告 | Self-reported |
| 你已验收 | 你已验收 | 受け入れ済み | You accepted |
| 报告过期 | 报告已 {days} 天 | 報告から {days} 日 | Report is {days} days old |
| 没有快照 | 还没有快照 | スナップショットはまだありません | No snapshot yet |
| 休息日 | 今天是休息日，需要你决定的事会等你。 | 今日は休みの日。判断が必要なことは待っていてくれます。 | Rest day. Decisions can wait. |

日文和英文在 P2 统一过一遍，并检查三种语言在窄屏下的长度和换行。

## 16. 无障碍

- 语义结构：跳到正文的链接、`header / nav / main` 地标、导航用列表、表格有表头。
- 键盘：所有操作可达；对话框聚焦锁定、`Esc` 关闭、关闭后焦点回到触发按钮；里程碑表可以逐行操作。
- 可见的 `:focus-visible` 焦点环，两种主题都清楚。
- 对比度：正文 ≥ 4.5:1，图形和边界 ≥ 3:1，浅色深色各验一次。
- 颜色不是唯一线索：所有状态都有图形和文字。
- 不依赖悬停：悬停提示同样在聚焦时出现；关键信息不藏在悬停里。
- 触控目标 ≥ 44px（手机）。
- 导入结果、操作结果用 live region 播报。
- 减少动画偏好生效。
- 每张小图（里程碑格、时间带）都有对应的文字或表格。

## 17. 每个页面完成前的检查

桌面和 375px 窄屏各看一次；浅色深色各看一次；键盘从头走到尾；对比度；中日英三种界面语言的长度和换行；减少动画偏好；用真实快照而不是占位内容。
